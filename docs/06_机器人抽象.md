# 设备抽象

## 模块定位

`device` 模块定义机器人、相机和其他外设的统一接口。

运行时只依赖统一设备接口，不依赖具体厂家 SDK。

## 机器人接口

机器人统一接口为 `IRobot`。

接口职责包括：

- 关节运动。
- 直线运动。
- 数字输出。
- 数字输入等待。
- 延时动作。

运行时执行 `Action` 时，根据 `TaskActionType` 调用 `IRobot` 对应方法。

当前 `IRobot` 使用统一方法屏蔽底层 SDK 差异：

- `MoveJoint(action_parameters)`
- `MoveLinear(action_parameters)`
- `SetDigitalOutput(action_parameters)`
- `WaitDigitalInput(action_parameters, timeout_ms)`
- `Delay(action_parameters, timeout_ms)`

这意味着运行时统一调动作，具体厂家 SDK 翻译由设备实现负责。

## 相机接口

相机统一接口为 `ICamera`。

相机接口用于获取视觉结果，例如抓取位姿。

视觉动作在任务模型中应表现为普通 `Action`，例如请求相机位姿、等待结果并写入参数。

## 设备实现

具体设备实现放在 `device` 模块下。

示例机器人实现：

```text
include/robot_process_platform/device/robot/hy_robot.h
src/device/robot/hy_robot.cpp
```

设备实现可以是：

- 真实厂家 SDK 适配器。
- 调试用设备实现。
- 仿真设备。

当前项目中的 `HyRobot` 是占位实现，用于验证任务执行链、日志和运行时行为，不代表真实厂家适配已经完成。

当前 `HyRobot` 已具备两种实现形态：

- mock 形态：默认执行模式，用于验证平台主链。
- 华沿 SDK 形态：通过 CMake 选项编译启用，底层调用 `HR_Pro.h + libHR_Pro.so`。

当前已接入的华沿 SDK 能力包括：

- 连接与断开。
- 关节运动。
- 直线运动。
- 控制箱 DO 输出。
- 控制箱 DI 轮询等待。
- 运动完成轮询。

`HyRobot` 当前仍通过统一 `IRobot` 对外暴露这些能力。

## 运行时边界

运行时只调用设备统一接口。

运行时不关心：

- 机器人品牌。
- 通信协议。
- SDK 类型。
- 相机厂家。
- 外设连接细节。

厂家差异由设备实现或适配层消化。

## 连接边界

机器人连接不属于 runtime 执行动作。

正确边界是：

- 设备对象本身可以提供 `Connect / Disconnect / IsConnected`。
- 平台或设备管理流程负责显式触发连接。
- `RuntimeService` 和 `TaskRunner` 只消费已经准备好的 `IRobot` 对象。

因此，运行时执行动作时不会隐式建立机器人连接。
