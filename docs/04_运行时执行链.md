# 运行时执行链

## 运行时职责

运行时只负责执行生成后的 `Task`，不负责生成任务。

因此运行时的标准输入是：

- `Task`
- `ExecutionContext`
- 接入平台的机器人或设备接口

运行时不直接接收：

- 原始工艺 json
- 模板名称
- 模板参数
- `ProcessPlan`

这些内容属于模板层和平台服务层的职责。

## 运行时定位

运行时当前分成两层：

- `RuntimeService`：常驻线程、命令队列、状态快照。
- `TaskRunner`：同步执行核心，按 `Action` 推进。

运行时主链包括：

- 加载任务
- 启动任务
- 按 action 推进
- 使用 block 作为调度和语义边界
- 记录执行位置
- 支持暂停、恢复、停止、急停等控制入口

当前运行时已经具备专用线程宿主 `RuntimeService`，但仍不承担以下职责：

- `SafetyManager`
- `DeviceManager`
- action 执行中打断
- 实时运动控制
- EventBus 广播

机器人实时控制、插补、伺服周期由机器人控制器负责，不由本平台运行时负责。

## 核心组件

运行时由以下组件组成：

- `RuntimeService`
- `TaskRunner`
- `StateMachine`
- `BlockScheduler`
- `BlockQueue`
- `BlockExecutor`
- `ExecutionContext`

### RuntimeService

`RuntimeService` 是当前运行时线程宿主。

它的职责是：

- 启动和停止运行时线程。
- 维护命令队列。
- 串行处理运行时命令。
- 持有并保护 `ExecutionContext`。
- 在 `Running` 状态下调用 `TaskRunner::Tick()`。

### TaskRunner

`TaskRunner` 是运行时编排器。

它不直接决定工艺逻辑，也不直接理解模板含义，只负责把下面几个组件串成执行链：

- `StateMachine`
- `BlockScheduler`
- `BlockQueue`
- `BlockExecutor`

`TaskRunner` 提供以下控制入口：

```cpp
LoadTask(task, context)
Start(context)
Tick(context)
Pause(context)
Resume(context)
Stop(context)
EmergencyStop(context)
ResetFault(context)
```

`RunTask(task, context)` 是同步执行入口，内部复用：

```text
LoadTask
Start
Tick loop
```

### Tick

`Tick()` 是运行时的“推进一步”接口。

定义为：

```text
一次 Tick = 尝试推进并执行一个 Action
```

它不是机器人实时控制周期，也不是伺服周期。

它只是平台任务层面的推进周期。

`ExecutionBlock` 仍然存在，但它不再是一次 `Tick()` 的执行粒度。

含义如下：

```text
ExecutionBlock = 一组连续的 Action 边界
Tick = 执行 active block 内的下一个 Action
```

一次 `Tick()` 的执行流程为：

```text
Tick()
    |
    | 检查是否加载 Task
    |
    | 检查 runtime_state 是否为 Running
    |
    | StateMachine 判断是否允许继续运行
    |
    | 如果没有 active block，BlockScheduler 从 Task 中取下一个 ExecutionBlock
    |
    | BlockQueue 保存 active block
    |
    | BlockExecutor 执行 active block 内的下一个 Action
    |
    | 更新 ExecutionContext.current_block_index / current_action_index
    |
    | 如果 active block 全部 action 完成，StateMachine 接收 BlockCompleted
    |
    v
返回
```

如果 `BlockScheduler` 找不到下一个 block，说明任务已经执行完：

```text
BuildNextQueuedBlock == false
    |
    v
StateMachine.HandleEvent(TaskCompleted)
    |
    v
runtime_state = Completed
```

### StateMachine

`StateMachine` 只负责状态迁移和推进条件判断。

它不执行动作，也不判断工艺逻辑。

状态包括：

- `Idle`
- `Ready`
- `Running`
- `Paused`
- `Fault`
- `EmergencyStop`
- `Stopped`
- `Completed`
- `Failed`

状态原则：

- 只有 `Running` 状态允许继续推送 block。
- `Paused` 状态不继续推送 block。
- `Fault` 状态表示执行失败或设备动作失败。
- `EmergencyStop` 表示外部安全系统要求急停。
- `Stopped` 表示普通人为停止。

### BlockScheduler

`BlockScheduler` 负责从 `Task` 中找到下一个应该执行的 `ExecutionBlock`。

调度策略：

```text
next_block_index = current_block_index + 1
```

它不负责执行 block，也不负责判断 block 内 action 是否合理。

### BlockQueue

`BlockQueue` 是单槽队列。

队列只保存一个待执行 block。

该设计用于保持执行语义清晰：

- 不做多 block 预取
- 不做复杂优先级
- 不让还没确定安全状态的 block 提前堆积

### BlockExecutor

`BlockExecutor` 只负责消费队列中的 block。

它的职责是：

- 从指定 action index 开始执行
- 顺序执行 block 内部 action
- 调用 `IRobot` 或其他设备接口
- 更新 `ExecutionContext.current_action_index`
- 动作失败时写入 `ExecutionContext.last_error`

它不负责：

- 判断下一个 block 是谁
- 判断运行状态是否允许执行
- 处理模板逻辑
- 处理安全检测

### ExecutionContext

`ExecutionContext` 是任务运行时状态记录。

记录内容：

- `runtime_state`
- `task_id`
- `template_name`
- `current_block_index`
- `current_action_index`
- `last_error_code`
- `last_error`

它是恢复机制的基础。

## 两种执行入口

### 直接使用 TaskRunner

标准调用方式：

```cpp
task_runner.LoadTask(task, context);
task_runner.Start(context);

while (context.runtime_state == RuntimeState::Running)
{
    task_runner.Tick(context);
}
```

### 通过 RuntimeService

推荐系统级执行方式：

```text
StartService
    ->
SubmitLoadTask(task)
    ->
SubmitStartTask()
    ->
RuntimeService 线程内部驱动 Tick
```

## TaskRunner 执行流程

`TaskRunner` 对应流程为：

```text
Task
 |
 | LoadTask(task)
 v
ExecutionContext 初始化
runtime_state = Ready
current_block_index = start_block_index - 1
current_action_index = -1
 |
 | Start()
 v
runtime_state = Running
 |
 | Tick()
 v
StateMachine 判断是否允许继续运行
 |
 v
如果没有 active block，BlockScheduler 取下一个 ExecutionBlock
 |
 v
BlockQueue 保存 active block
 |
 v
BlockExecutor 执行 active block 内的下一个 Action
 |
 v
IRobot / Device 接口执行具体动作
 |
 v
ExecutionContext 更新 block/action 位置
 |
 v
如果 active block 内 action 全部完成，触发 BlockCompleted
 |
 v
下一次 Tick()
```

## 暂停、恢复、停止、急停

### 暂停

暂停通过 `TaskRunner::Pause()` 触发。

暂停语义：

- 正在执行的 action 不会被中途打断。
- 暂停后状态进入 `Paused`。
- `Tick()` 不再执行下一个 action。

### 恢复

恢复通过 `TaskRunner::Resume()` 触发。

恢复语义：

- 从 `Paused` 回到 `Running`。
- `Tick()` 继续推进下一个 action。

### 普通停止

普通停止通过 `TaskRunner::Stop()` 触发。

停止语义：

- 清空 `BlockQueue`。
- 解除 loaded task。
- 状态进入 `Stopped`。

普通停止和急停不同，它是人为终止任务，不代表安全系统触发。

### 急停

急停入口为 `TaskRunner::EmergencyStop()`。

但 `TaskRunner` 不负责检测急停。

职责划分为：

```text
HMI / 安全系统 / 设备报警来源
        |
        | 检测急停、安全门、光栅、机器人报警等
        v
外部控制层
        |
        | 通知任务必须急停
        v
TaskRunner::EmergencyStop()
        |
        | 清空队列，停止继续推进 block
        v
runtime_state = EmergencyStop
```

也就是说：

- `TaskRunner` 负责“任务如何停”。
- 外部安全或控制系统负责“为什么必须停”。
- 外部控制层负责把控制请求转成运行时调用。

`TaskRunner` 不应该直接读取急停 IO，也不应该直接判断安全门状态。

## 边界约束

- 运行时不负责查找模板。
- 运行时不负责解析工艺 json。
- 运行时不负责生成 `ProcessPlan`。
- 运行时不负责 `CreateTask`。
- 运行时只负责输入 `Task` 的执行推进。
- 模板层负责生成 `Task`。
- 平台服务层负责模板管理、任务管理、任务保存。
- 安全系统负责检测安全条件。
- 设备层负责屏蔽机器人、相机等厂家差异。
