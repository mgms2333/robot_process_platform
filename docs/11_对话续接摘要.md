# 对话续接摘要

这份文档用于新一轮对话快速接续当前项目状态。内容以当前代码和已确认设计为准，不记录开发过程。

## 1. 项目当前阶段

项目已经进入：

```text
平台主链已闭环，运行时已服务化，开始进入平台协调层和真机器人接入阶段
```

当前已经跑通的主链是：

```text
模板加载
-> 输入 JSON 生成 Task
-> Task 保存
-> Task 读回
-> RuntimeService 执行
-> TaskRunner 按 Action 推进
-> HyRobot 执行动作
```

`runner` 当前可完整跑到：

```text
runtime_state = Completed
```

```text
HMI / Runner / API
```

## 3. 当前核心模型

执行端统一模型已经稳定：

```text
Task
-> ExecutionBlock
-> Action
```

当前 `Action` 结构包含：

- `action_name`
- `action_type`
- `action_parameters`
- `timeout_ms`

当前动作类型包括：

- `MoveJoint`
- `MoveLinear`
- `SetDigitalOutput`
- `WaitDigitalInput`
- `Delay`

当前动作参数仍然采用：

```cpp
std::map<std::string, std::string>
```

也就是说：

- 动作种类已经统一
- 参数模型还没有完全强类型化
- 模板和设备实现之间仍有一层参数约定

## 5. Runtime 进度

当前已经完成：

- `RuntimeService`
- `TaskRunner`
- `StateMachine`
- `BlockScheduler`
- `BlockQueue`
- `BlockExecutor`
- `ExecutionContext`

关键语义：

- `Tick()` 是 action 级推进
- 一次 `Tick()` 最多执行一个 `Action`
- `RuntimeService` 是线程宿主
- `TaskRunner` 是运行时编排器
- `StateMachine` 负责迁移规则
- 当前状态值保存在 `ExecutionContext.runtime_state`
- `StateMachine` 不持有状态值，只负责迁移规则

## 11. 关键设计结论

### 11.1 创建任务和运行任务必须分开

这一点已经明确确认：

```text
CreateTask 和 StartTask 在逻辑上必须分开
```

不能让“点击运行”默认变成“再新建一个 task”。

### 11.2 StartTask 应统一为“指定 task，从指定位置开始运行”

这一点也已经明确确认：

```text
所有运行，本质上都是“运行指定 task，从某个步骤开始”
```

当前已统一成：

```text
StartTask(task_id, task_dir, start_block_index, start_action_index)
```

默认从头开始就是：

```text
StartTask(task_id, task_dir, 0, 0)
```

断点恢复就是：

```text
StartTask(task_id, task_dir, block_index, action_index)
```

### 11.3 当前 PlatformService 的 StartTask 语义已收敛

当前 `PlatformService::StartTask(...)` 已不再创建任务，只负责：

- 按 `task_id` 从任务目录加载已保存 task
- 将 task 和起始位置提交给 `RuntimeService`
- 提交 runtime start 命令

### 11.4 设备配置已开始 JSON 化

这一点已经明确确认：

- robot 配置
- camera 配置
- 485 配置
- IO 映射

都不应依赖重新编译。

当前已经落地：

- 新增 `config/platform_config.json`
- `PlatformService::Initialize()` 支持按配置文件路径初始化
- 默认入口读取 `./config/platform_config.json`
- 华沿 robot 的 host、端口、SDK 开关、默认速度/加速度、IO 映射等已从 JSON 读取

代码中不再硬编码现场 robot 地址。

## 12. 下一步建议

优先级建议如下。

### 第一优先级

评估并收敛 `Action` 参数模型。

当前 `Action` 已有统一类型，但参数仍是：

```cpp
std::map<std::string, std::string>
```

这对模板快速生成和 JSON 持久化很轻，但对真机器人接入、参数校验、错误定位不够强。

### 第二优先级

继续完善设备配置 JSON 化：

- camera 配置
- 485 配置
- IO 映射约定
- 多机器人/多设备注册策略

## 13. 对话续接时的建议入口

如果下一轮对话要继续，最建议的起点是：

```text
先评估 Action 参数模型是否需要从 map<string,string> 演进为“typed payload + 校验层”。
```
