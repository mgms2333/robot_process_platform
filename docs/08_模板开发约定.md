# 模板开发约定

## 模板放置原则

具体工艺模板必须单独放在 `plugins/` 目录下，不和平台主体源码混放。

当前约定如下：

- 平台主体只定义模板抽象和模板相关的公共模型
- 码垛、焊接、上下料等模板作为独立工艺扩展存在
- 每个模板目录应独立维护自己的头文件、源码和说明文档

## 模板开发范式

模板必须遵循两阶段结构：

1. `Plan`
   输入模板内部强类型参数
   输出 `ProcessPlan`

2. `BuildTask`
   输入 `ProcessPlan`
   输出统一 `Task`

## 哪些属于模板能力

以下内容属于模板内部职责：

- 模板专属参数解析
- 参数合法性检查
- 工艺规划
- 工艺块拆分
- `ProcessPlan` 生成
- `Task / ExecutionBlock / Action` 展开

## 哪些不属于模板能力

模板不允许承担以下职责：

- 创建任务 ID 规则管理
- 任务持久化
- 模板加载与卸载
- 状态机迁移
- 安全联锁
- 报警处理
- 恢复流程
- 系统事件广播

## 当前示例模板

当前提供一个码垛模板示例，位于：

- `plugins/palletizing/include/palletizing/palletizing_template.h`
- `plugins/palletizing/src/palletizing_template.cpp`

这个示例的目的不是实现完整码垛逻辑，而是固定后续模板开发的最小结构和代码风格。
