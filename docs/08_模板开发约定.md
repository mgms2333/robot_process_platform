# 模板开发约定

## 模板职责

模板负责把工艺输入转换成统一任务模型。

输入：

- 模板名称。
- 工艺上下文 JSON。

输出：

- `core::Task`

模板不直接执行机器人动作，也不直接调用设备接口。

## 模板目录

具体模板放在 `plugins/` 下。

示例：

```text
plugins/palletizing/
├── include/palletizing/
│   └── palletizing_template.h
└── src/
    ├── palletizing_template.cpp
    └── palletizing_plugin_entry.cpp
```

## 模板内部流程

模板内部采用两阶段结构：

```text
输入 JSON
    |
    v
ParseTaskParameters
    |
    v
BuildProcessPlan
    |
    v
BuildTask
    |
    v
core::Task
```

### ParseTaskParameters

解析模板输入 JSON，并转换成模板内部使用的强类型参数。

调用者不需要知道模板内部参数结构。

### BuildProcessPlan

根据模板参数生成工艺计划。

工艺计划表达“做什么”，不直接表达机器人底层动作。

### BuildTask

把工艺计划展开成平台统一任务模型。

输出结构为：

```text
Task
    |
    v
ExecutionBlock
    |
    v
Action
```

## 模板专用概念

模板可以定义自己的工艺语义对象。

例如码垛模板可以定义：

- 箱子。
- 层。
- 垛型。
- 抓取块。
- 过渡块。
- 放置块。

这些概念只存在于模板内部或模板输出元信息中。

运行时不依赖这些专用概念执行任务。

## 平台通用概念

模板输出必须落到平台通用概念：

- `Task`
- `ExecutionBlock`
- `Action`

运行时只消费这些通用对象。

## Action 参数约定

模板当前需要遵守平台已有动作参数约定。

常见约定如下：

- `MoveJoint / MoveLinear`
  - `target_pose`
  - 可选 `reference_joints`
  - 可选 `velocity / acceleration / radius`
- `SetDigitalOutput`
  - `signal_name` 或 `signal_bit`
  - `signal_value`
- `WaitDigitalInput`
  - `signal_name` 或 `signal_bit`
  - `expected_value`

模板不应假定运行时知道模板专用字段含义。
模板需要把工艺语义在 Build 阶段转换成平台能够消费的统一参数。

## 模板禁止承担的职责

模板不负责：

- 生成全局任务 ID 规则。
- 保存任务文件。
- 加载或卸载模板动态库。
- 调用机器人或相机接口。
- 控制运行时状态机。
- 处理安全联锁。
- 处理报警生命周期。
- 管理恢复流程。
- 发布系统事件。
