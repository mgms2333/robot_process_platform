# 核心模型

## 模块职责

`core` 模块定义平台执行端使用的通用静态任务模型。

该模块只描述数据结构，不包含模板生成逻辑、运行时调度逻辑、状态机逻辑和设备调用逻辑。

## 执行端模型

执行端统一模型为：

```text
Task
    |
    v
ExecutionBlock
    |
    v
Action
```

### Task

`Task` 表示一次完整任务实例。

主要字段：

- `task_id`：任务实例 ID。
- `template_name`：生成该任务的模板名称。
- `execution_blocks`：任务包含的执行块序列。

### ExecutionBlock

`ExecutionBlock` 表示执行层的调度边界。

一个 `ExecutionBlock` 包含一组应按顺序执行的 `Action`。

主要字段：

- `block_name`：执行块名称，用于日志、调试和界面显示。
- `semantic_type`：模板语义类型，例如 `box`、`seam`、`unit`。
- `semantic_index`：语义对象序号。
- `process_block_name`：来源工艺块名称，例如 `pick_block`。
- `actions`：该执行块内的动作列表。

### Action

`Action` 是运行时执行器直接消费的最小执行单元。

主要字段：

- `action_name`：动作名称。
- `action_type`：动作类型。
- `action_parameters`：动作参数。
- `timeout_ms`：动作超时时间。

当前 `Action` 参数仍采用：

```cpp
std::map<std::string, std::string>
```

这意味着：

- 平台已经统一了动作种类。
- 动作参数格式当前仍以约定为主。
- 参数强类型化仍是后续可继续收紧的方向。

## Action 类型

`TaskActionType` 定义平台运行时可识别的基础动作类型：

- `MoveJoint`
- `MoveLinear`
- `SetDigitalOutput`
- `WaitDigitalInput`
- `Delay`

模板必须把工艺语义展开为这些统一动作，运行时只识别统一动作类型。

当前常见参数约定包括：

- `MoveJoint / MoveLinear`
  - `target_pose`
  - 可选 `reference_joints`
  - 可选 `velocity / acceleration / radius`
- `SetDigitalOutput`
  - `signal_name` 或 `signal_bit`
  - `signal_value`
- `WaitDigitalInput`
  - `signal_name` 或 `signal_bit`
  - `expected_value`

## Step

`Step` 是保留的可读步骤结构。

执行端不直接调度 `Step`，运行时调度对象是 `ExecutionBlock`，执行对象是 `Action`。

## 模型边界

- `core` 不依赖厂商 SDK。
- `core` 不依赖模板实现。
- `core` 不依赖运行时状态机。
- `core` 不负责判断动作能否执行。
- `core` 不负责保存或加载任务文件。
