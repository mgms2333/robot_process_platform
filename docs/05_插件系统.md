# 插件系统

## 插件定位

插件系统用于把具体工艺模板从平台主体中分离出来。

平台主体只定义模板接口和模板通用类型，具体工艺模板放在 `plugins/` 目录下，以动态库形式加载。

## 模板接口

模板实现统一接口：

```cpp
class ITemplate
{
public:
    virtual std::string TemplateName() const = 0;
    virtual core::Task CreateTask(const std::string& task_context_json) = 0;
};
```

调用者只需要提供：

- 模板名称。
- 输入上下文 JSON。

模板内部负责解析 JSON、规划工艺、构建 `Task`。

## 动态库入口

模板动态库导出以下 C 接口：

```cpp
const char* GetTemplateName();
ITemplate* CreateTemplate();
void DestroyTemplate(ITemplate* template_instance);
```

平台通过这些入口完成模板识别、实例创建和实例销毁。

## 模板目录

具体模板目录结构：

```text
plugins/<template_name>/
├── include/
└── src/
```

示例：

```text
plugins/palletizing/
├── include/palletizing/
└── src/
```

## 平台与模板边界

平台负责：

- 加载模板动态库。
- 管理模板实例。
- 调用模板创建任务。
- 保存生成的任务。

模板负责：

- 解释输入 JSON。
- 生成工艺计划。
- 展开为统一 `Task`。
- 设置 `ExecutionBlock` 和 `Action` 参数。

模板不负责：

- 任务持久化。
- 模板加载与卸载。
- 运行时状态机。
- 机器人或设备直接调用。
- 安全、报警、事件和恢复逻辑。
