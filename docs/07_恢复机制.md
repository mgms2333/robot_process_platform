# 恢复机制

## 恢复基础

恢复机制依赖运行时上下文记录任务执行位置。

执行位置由 `ExecutionContext` 表示：

- `task_id`
- `template_name`
- `runtime_state`
- `current_block_index`
- `current_action_index`
- `last_error_code`
- `last_error`

## 恢复点语义

恢复点可以表示为：

```text
task_id
block_index
action_index
```

其中：

- `block_index` 表示恢复到哪个 `ExecutionBlock`。
- `action_index` 表示恢复到该 block 内的哪个 `Action`。

## 运行时恢复入口

`TaskRunner::LoadTask()` 支持从指定位置加载任务：

```cpp
LoadTask(task, context, start_block_index, start_action_index)
```

标准恢复流程：

```text
读取 Task
    |
    v
读取恢复点
    |
    v
LoadTask(task, context, block_index, action_index)
    |
    v
Start(context)
    |
    v
Tick loop
```

## 恢复边界

平台恢复的是任务执行位置，不恢复机器人底层运动状态。

如果机器人正在执行动作时发生异常，需要先由设备层、人工流程或安全流程把机器人恢复到可控状态，再从指定 `block/action` 继续执行。

如果运行前存在机器人连接、上电、控制器接管等准备动作，这些动作同样不属于恢复点的一部分。

## 模板边界

模板可以提供工艺语义信息，例如码垛箱序号、焊缝序号、工位号等。

运行时恢复只依赖统一 `Task / ExecutionBlock / Action` 位置。

工艺语义解释属于模板或上层应用，不属于运行时核心职责。
